A Distributed System is a system where multiple independent computers work together and appear to the user like one system.

Instead of doing everything on one machine, the work is spread across many machines.

These machines communicate over a network and co-ordinate with each other to achieve a common goal.

So, the main idea is -

    Many machines working together
    And
    Acting like one system.

For example, when you use a large application like an e-commerce site, you usually do not interact with just one server. Behind the scenes, there may be -
    
    1. Web servers
    2. Application servers
    3. Database servers
    4. Cache servers
    5. Message brokers
    6. Search servers

All these machines work together to serve one user request.

That is a distributed system.

# WHY DO WE USE DISTRIBUTED SYSTEMS?

But, why do we use them? Isn't it better to run everything on one machine?

Well, we use distributed systems because one system or machine is often not enough. As the systems grow, they need -

    1. More scale
    2. More availability
    3. More fault tolerance
    4. More storage
    5. More processing power

A single machine as its limits. For example, the CPU is limited, the memory is limited, the disk is limited, the network bandwidth is limited and if the machine crashes, the system may go down.

So, instead of relying on one machine, we spread the system across multiple machines.

This helps the system grow and survive the failures better.

Suppose a website gets millions of users. If everything runs on one server, problems can happen such as -

    1. Server becomes overloaded
    2. Database becomes slow
    3. One hardware failure brings everything down

Now, imagine the system is distributed -

    1. Multiple web servers handle requests
    2. A load balancer spreads the traffic
    3. Database replicas share the read load
    4. Cache servers reduce the database pressure
    5. Message queues handle background jobs

Now, the system can handle more traffic and recover better from failures. This is why distributed systems are so common.

# CHARACTERISTICS OF DISTRIBUTED SYSTEMS

Distributed systems usually have some common characteristics. For example -

    1. Multiple Nodes
    2. Network communication
    3. Coordination between machines
    4. Partial failures is possible
    5. Concurrency exists
    6. No single shared memory
    7. Independent scaling is possible

A node usually means one machine, server, or process participating in the system. The nodes communicate over a network instead of directly calling local memory.

That is a major difference from one single machine.

# WHY DISTRIBUTED SYSTEMS ARE HARD?

They are hard because once many machines work together, many new problems appear that do not exist, or are much smaller, in one single machine system.

The biggest reason is -

    1. Machines can fail independently
    2. Networks can fail independently
    3. Communication takes time
    4. System state is spread out

So now, the system has to deal with uncertainty.

In a single machine system, a function call usually either works or throws an error quickly.

But, in a distributed system, a remote call may mean many different things like -

    1. Request was never sent
    2. Request was sent but never received
    3. Request was received but response got lost
    4. Request was processed twice
    5. Remote service is slow
    6. Remote service is down
    7. Network is partitioned

This uncertainty makes reasoning much harder.

## PARTIAL FAILURE

One of the biggest challenges is 'Partial Failure' which means one part of the system fails while other parts still work. For example -

    Service A is healthy
    Service B is healthy
    Service C is down

OR

    Server is healthy
    But network path to it is broken

This is very different from a single machine failure. In distributed systems, some things may work while others may not. That makes debugging and recovery harder.

## NETWORK PROBLEMS

A network is not like a local function call. Networks can be slow, unreliable, partitioned, congested, and temporarily unavailable. This means communication between nodes is never perfectly certain.

Even if both machines are healthy, the network between them may still create failures.

So, distributed systems must always assume that network communication is risky.

## LATENCY

In a single process, many operations happen very fast. In distributed systems, communication between machines adds latency.

For example -

    Local memory access may be extremely fast
    Network calls are much slower

If one user request requires calls across many services, latency adds up. That is why distributed systems need careful design around communication.

## CONSISTENCY

Since data may exist on multiple machines, keeping it consistent becomes hard. For example -

    One replica has new value
    Another replica still has the old value

OR

    One service updated successfully
    Another related service has not updated yet

So, now the question becomes -

    What is the correct state right now?

This is one of the central problems in distributed systems. That is why topics like replication, eventual consistency, distributed transactions, saga pattern matter.

## TIME AND CLOCKS

Time is surprisingly tricky in distributed systems. Different machines have different clocks and those clocks may drift. Messages may arrive late or out of order.

So, it is dangerous to assume that all machines agree perfectly on time. This creates problems in ordering, coordination, expiry, locking and debugging.

## COORDINATION

Sometimes machines need to agree on something like -

    1. Who is the leader?
    2. Which node owns this work?
    3. Has this transaction committed?
    4. Should this lock be granted?

Getting many independent machines to agree is difficult, especially when failures and delays happen. That is why coordination and consensus are such important topics.

## SCALING ADDS COMPLEXITY

Distributed systems help scale, but scale itself introduces more problems. For example -

    - More nodes
    - More messages
    - More retry cases
    - More monitoring needs
    - More failure combinations

So, distributed systems solve one problem by introducing another layer of complexity.

That is why it is said -

    Distributed systems are built because they are necessary,
    not because they are simple

## OBSERVABILITY IS HARDER

In one machine system, it is often easier to inspect state and logs. But in distributed systems, one user action may touch many services.

For example -

    - API Service
    - Payment Service
    - Inventory Service
    - Notification Service

So, to understand one failure, you may need logs, traces, and metrics from many places. That makes observability much more important.

# TRADEOFFS

Distributed systems are full of tradeoffs likes -

    - More consistency may reduce availability
    - More coordination may reduce performance
    - More replication may improve reliability but complicate writes
    - More retries may improve success but create duplicate effects

There is rarely one perfect answer. Design usually means choosing which tradeoff is acceptable for a specific use case.

# MICROSERVICES AND DISTRIBUTED SYSTEMS

Microservices are one style of building distributed systems. A microservices system is usually distributed because many services run on different machines and communicate over the network.

But, not very distributed system is a microservices system. For example -

    A distributed database is a distributed system, even though it is not a set of business microservices.

So -
    
    Distributed systems is the bigger concept
    Microservices is one architectural style inside that world

Remember that a distributed system is not just "many servers." It is many independent components that must communicate, coordinate, and tolerate failure while still behaving like one useful system.

And the reason it is hard is not only scale. The real difficulty is uncertainty.

The system must work even when -

    - Some machines are slow
    - Some machines are down
    - Some messages are delayed
    - Some data is stale
    - Some operations happen twice

A distributed system is a system where multiple machines work together as one, and it is hard because communication, coordination, consistency, and failure all become much more complicated across many machines.
